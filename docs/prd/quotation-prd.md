## **1. 概述**

本模組負責 ERP+CRM 系統中報價單的建立、簽核及生命週期管理。功能包含分步建立流程 (Step 1 -> Step 2 -> View Page)、專案編輯器連動、全方位投放鎖定、**Ticket (工單) 連動**，以及與發票發送、帳務提醒等核心邏輯。

## **5. 業務邏輯與規則 (Business Logic)**

### **5.1 簽核流程 (規則 1)**

- **組員啟動簽核**：
    - < 50 萬：John/Daniel/Ingrid -> Bella 或 Gillian/Cola -> Eric
    - >= 50 萬：(上述組長) -> River Yang
- **小組長啟動簽核**：Bella/Eric -> River Yang

### **5.2 狀態轉換與鎖定規則 (規則 2 / 3 / 4)**

- **Rule 2**：狀態為「確認執行」後改銷售明細、預算、走期需重新簽核。**惟已發出「AS 素材確認通知」Ticket 後禁止修改明細。**
- **Rule 3**：改 Campaign 名稱需通知執行投手。
- **Rule 4**：狀態為「確認執行」時，不可修改「代理商、客戶、品牌」。

### **5.3 Lark 工單 API 串接 (Lark Ticket Integration)**

報價單模組不再維護內部工單，改為與外部 **Lark (飛書) 工單系統** 透過 API 進行雙向整合。

### **5.3.1 觸發與推送 (Outbound - Push to Lark)**

當業務人員於報價單頁面點擊「開立工單」並選擇類型時，系統透過 API 發送 Payload 至 Lark：

- **介接 API**：`Lark.Flow.CreateTicket`
- **推送欄位**：
    - `quotation_no`：報價單號
    - `campaign_name`：活動名稱
    - `customer_name`：客戶名稱 (Snapshot)
    - `owner_name`：負責業務
    - `ticket_type`：工單類型 (如下表)
    - `deep_link`：連回 TopSale 報價單之 URL

### **5.3.2 狀態同步 (Inbound - Sync from Lark)**

TopSale 透過 **Webhook** 接收來自 Lark 的狀態更新：

- **同步邏輯**：當 Lark 工單狀態變更（如：已受理、處理中、已完成）時，自動回寫至報價單底部的「工單追蹤區」。
- **顯示內容**：顯示工單編號、處理人及最後異動時間。

### **5.3.3 工單類型清單**

| 負責團隊 | 工單類別名稱 (Lark Template) | 備註 |

### **5.4 抽單、加碼與通知規則**

- **完全抽單**：
    - **觸發條件**：報價單狀態為「確認執行」，客戶決定整筆不執行。
    - **執行動作**：負責業務執行「完全抽單」。
    - **系統動作**：狀態變更為「已抽單」，並**自動通知「此案負責投手」及「直屬主管」**。
- **部份抽單**：
    - **觸發條件**：報價單狀態為「確認執行」，客戶決定部分品項不執行。
    - **執行動作**：負責業務執行「部分抽單」，並選取特定 Item 修改預算金額。
    - **系統動作**：**自動通知「此案負責投手」及「直屬主管」**，紀錄修改歷史。
- **加碼 (Top-up) / 減項 (Reduction)**：
    - **觸發條件**：報價單狀態為「確認執行」，需調整預算總額。
    - **執行動作**：負責業務執行「加碼」或「減項」，並修改產品明細。
    - **簽核流程**：系統自動發起 **Lark 審核工單**。簽核通過前，金額不變動。
    - **系統動作**：簽核通過後，自動寫入 `Quotation_Revision_Log`，並更新 `Quotation_Final_Net` 為累計後之最新總額。
- **發票通知**：走期結束 3日/2週/1月仍有未開金額，通知業務。
- **欠款通知**：AR 逾期 2週/1月，通知業務。

### **5.5 贈送 (Bonus) 規則**

- 當報價類別選擇「贈送」時，系統應支援選取 `產品 (SAD)` 或 `服務 (SVC)` 主檔。
- 選取後，報價單明細中的單價與金額應強制鎖定為 0。
- PDF 匯出時應明確標註「贈送 (Bonus)」。

### **5.7 報價單連動聯盟 (Affiliate Linkage)**

- **單一資料源概念 (SSOT)**：聯盟報價單與主報價單為**同一筆資料庫紀錄 (Shared UUID)**，非獨立副本。
- **偵測機制**：當報價單 STEP 1 選定的「客戶 (Account)」在 CRM 中的「聯盟 (Alliance)」屬性包含 `APEX` 或 `Omnet` 時，系統自動啟用此連動流程。
- **操作流程**：
    1. 業務照常填寫 STEP 1 (基本資料)、STEP 2 (產品明細) 以及 Section 4 (投放條件)。
    2. 填寫完畢後，View Page 會出現「**進入聯盟模組檢視**」按鈕。
- **即時同步規則**：
    - 業務在 3-1 進行的任何明細修改，均會即時反應在 3-2 模組介面中（反之亦然）。
    - 業務啟動「確認執行」簽核流程時，聯盟模組內容亦同步進入簽核中狀態。
- **權限控制**：
    - 此案件在主模組 (3-1) 中，業務**完全不可見**「折扣 (Discount)」與「折扣後金額」。
    - 折扣後之 PDF 匯出與發票拋轉功能，強制僅限在 3-2 模組中由指定人員執行。
- **狀態鎖定**：一旦報價單狀態變更為「確認執行」，主明細內容將全面鎖定。如需修改，需依據 5.2 節規範重新啟動簽核或由聯盟模組退回。

## **6. 專案編輯器細節 (Project Editor Details)**

當業務員在 STEP 2 的「類別」選擇 **專案 (PKG)** 時，系統應自動調用專案編輯器介面。

### **6.1 互動流程 (Interaction Flow)**

1. **觸發編輯器**：於產品名稱欄位點擊時，彈出「專案屬性編輯視窗」。
2. **顯示規則**：視窗右側顯示該專案在「產品模組 (Master Catalog)」定義的 **組成規則 (Composition)** 與 **贈送規則 (Bonus)**。
3. **品項挑選**：
    - **必選品項**：預設勾選且不可取消。
    - **選配品項**：業務員可根據預算需求，從篩選清單中加選。
    - **贈送勾選 (Bonus)**：
        - 符合贈送規則的品項可勾選「Bonus」，勾選後單價自動鎖定為 0。
        - **比例調整**：業務員可手動下修贈送的數量或比例（例如主檔送 10%，業務可改送 8%）。
        - **上限校驗**：系統必須阻擋任何超過主檔定義「贈送上限」的輸入值。
4. **確認帶回**：點擊「確認」後，編輯器會將選取的項目攤平並寫入 `Quotation_Line_Item`，且標記關聯之專案 ID。

### **6.2 運作邏輯 (Logic)**

- **即時試算**：編輯器內提供小計功能，顯示加選/取消品項後的預估總額。
- **雙重校驗 (Validation)**：
    - **門檻校驗**：若總額低於「起報門檻」，禁止帶回。
    - **贈送校驗**：若贈送品項的數量/比例超過主檔定義之「上限值」，禁止帶回並提示錯誤。
- **資料連動**：若後續修改專案主檔規則，已建立的報價單內容不自動更新（除非業務員重新開啟編輯器觸發重新載入）。

## **7. 輸出與附件 (Output & Attachments)**

- **PDF 匯出規則**：
    - 合併 Page 1 + Page 2。
    - **Page 2 內容**：緊接在 Page 1 總計區塊下方。
    - **欄位過濾**：未填寫項目匯出時不顯示。
    - **儲存格優化**：Section 4 之「鎖定類型」若內容重複，匯出時應執行 **垂直合併儲存格** 顯示。
    - **章印**：甲方媒體發稿章下自動帶入數位章。
    - **Page 3**：產品、專案、服務之特別注意事項。
- **Ticket 記錄**：報價單底下記錄所有已連動的 Ticket 狀態。
- **檔案夾帶**：支援上傳客戶回傳之用印檔案。

### **8.3 拋轉發票程序 (Forwarding to Invoice)**

- **執行條件**：報價單狀態為 **【確認執行】** 且已上傳 **【用印檔案】**。
- **操作規則**：
    - 支援多次拋轉。
    - **待開票判定**：`IF Quotation_Final_Net > invoiced_amt` -> 顯示於 Pending Dashboard。
    - **金額限制**：總拋轉之開票金額（扣除折讓後）不可超過 `Quotation_Final_Net`。
